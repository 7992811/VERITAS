# Brent: один закреплённый источник

## Правило владельца

7 октября 2026: «По нефти опять контракт не подтвержден, возьми один источник
информации и зафиксируй его в нефти».

Для новых модельных решений BRENT закреплена одна лента ProFinance:

| Поле | Значение |
|---|---|
| Источник | ProFinance |
| Название ленты | `Brent oil` |
| Тикер поставщика | `brent` |
| Идентификатор строки котировки | `27` |
| Поле текущей цены | `LP` |
| Тип цены свечей | `Last`, `ba=2` |
| Канонический источник | `PROFINANCE:Brent oil` |
| Версия закрепления | `PROFINANCE_BRENT_PIN_V1` |
| Минимальное число источников | 1 |

## Наблюдаемое подтверждение

Проверка 07.10.2026 20:25:01 МСК (17:25:01 UTC) получила HTTP 200 от
`https://jq.profinance.ru/html/htmlquotes/q`: `S=Brent oil`, `TICK=brent`,
`I=27`, `LP=+100.16`, `T=20:25:00`.

В 20:25:02 МСК ответ
`https://charts.profinance.ru/html/charts/refresh?s=Brent+oil` подтвердил
`s;Brent oil`, `t;brent`, `n;Last;2`. История запрашивается через
`https://charts.profinance.ru/html/charts/history` с `s=brent`, `ba=2`.

Эти ответы подтверждают инструмент у поставщика. Они не сообщают биржевой
месяц поставки. Поэтому `27` сохраняется как `provider_instrument_id`,
`contract_id` остаётся `null`, а `exact_contract_verified` — `false`.
Непрерывность либо конкретный месяц фьючерса не выводятся из названия ленты.

## Причина повторной надписи

До исправления котировка, свечи и открытые нефтяные позиции уже использовали
ProFinance. Журнал `market_verified` за 20:17:11 МСК показывал успешную
проверку одного источника. Интерфейс при любом пустом `contract_id` выводил
«месяц контракта не подтверждён», даже когда сама лента была определена.

Дополнительно идентификация принимала отсутствующий `TICK`, не закрепляла
`I`, а сравнение идентичности считало отсутствующий месяц совместимым с
произвольным новым месяцем. Эти границы исправлены в самой обработке данных.

## Постоянное поведение

1. Приём текущей нефти требует совпадения всех трёх полей: названия, тикера
   и идентификатора строки. Одного выставленного флага проверки недостаточно.
2. График отдельно подтверждает название и тикер. Свечи 1 мин, 5 мин,
   1 ч, 4 ч и дневные свечи сохраняют идентичность закреплённой ленты.
3. Допуск и окончательная запись новой позиции повторяют проверку
   фактической котировки. Привязка сохраняется при открытии и доборе,
   в переоценке, защитном выходе и журнале сделки.
4. Обновление котировки нового нефтяного сигнала обращается к ProFinance.
   Старый биржевой код из общего кэша не выбирает поставщика нового входа.
5. Ошибка источника не переключает BRENT на Yahoo, MOEX либо другую ленту.
   Ранее наблюдавшаяся котировка того же источника пригодна только в пределах
   действующей проверки времени. Историческая свеча не становится ценой входа.
6. Старые позиции сохраняют свой записанный источник. Для старого точного
   контракта MOEX защитная котировка по-прежнему запрашивает его сохранённый
   код. История цен входа, объёмов, расходов и финансового результата не
   переписывается при закреплении новой политики.
7. API различает закреплённый источник (`PINNED_PROVIDER_FEED`), наличие
   текущего подтверждения ленты и подтверждение биржевого месяца. В интерфейсе
   закреплённая лента подписана «ProFinance · Brent (brent) · источник закреплён».

## Проверки выпуска

Автоматические проверки покрывают отсутствующий и чужой тикер/идентификатор,
попытку подставить месяц, несовпадающий ответ графика, устаревшую котировку,
сохранение старой привязки позиции, отказ от чужой переоценки и проверку
источника перед окончательной записью. Закреплённые поля включены в краткие
представления открытых и закрытых сделок, чтобы они сохранялись после чтения
из базы. Обязательный набор проверок включён в VERITAS Safety CI.
