# Автоматическая диагностика валютного портфеля

`veritas_currency_automation_report.py` собирает проверяемый отчёт о программе,
чтении песочницы и подключении Telegram. `render_html()` создаёт отдельную
страницу на русском языке, пригодную для телефона. Модуль не обращается к
брокеру, Telegram или базе данных, не меняет настройки и не выдаёт разрешение
на исполнение. Его результат нельзя использовать как допуск к реальной торговле.

## Получение отчёта

В корне проекта:

```sh
PYTHONDONTWRITEBYTECODE=1 python tools/run_currency_automation_report.py \
  --run-offline --output-dir /tmp/veritas-currency-diagnostics
```

Команда выполняет выбранные проверки в отдельном процессе с тайм-аутом не более
60 секунд. Процесс получает только минимальное окружение; настройки подключения
и секреты родительского процесса в него не передаются. Соединения через сокеты
в процессе проверки отключены. Список модулей фиксирован:

- `test_veritas_offline_order_cycle` — полный цикл на имитации брокера;
- `test_veritas_currency_rule_consistency` — согласованность правил;
- `test_veritas_currency_console_telegram` — личная привязка на имитации Telegram;
- `test_veritas_currency_trade_ui` — договорённости интерфейса;
- `test_veritas_currency_sandbox_probe` — проверка песочницы на имитации HTTP;
- `test_veritas_currency_automation_report` — достоверность и обезличивание отчёта.

Проверки PostgreSQL и полная проверка выпуска выполняются отдельно. Этот набор
не заменяет их. Подпроцесс не выводит необработанные ошибки или ответы сервисов
в публичный отчёт.

В каталоге результата появляются `report.json`, `index.html` и
`offline-evidence.json`. Последний файл содержит число выполненных, успешных,
пропущенных и ошибочных тестов, время и отпечаток исходного кода. Для повторного
сбора страницы можно передать его через `--offline-evidence`. Произвольный
входной файл при этом не копируется в публичный каталог.

Свежие наблюдения передаются отдельно:

```sh
PYTHONDONTWRITEBYTECODE=1 python tools/run_currency_automation_report.py \
  --offline-evidence /tmp/veritas-currency-diagnostics/offline-evidence.json \
  --sandbox-report /tmp/currency-sandbox-observation.json \
  --telegram-observation /tmp/currency-telegram-observation.json \
  --output-dir /tmp/veritas-currency-diagnostics
```

Команда не выполняет сетевую проверку сама. `--sandbox-report` принимает результат
`veritas_currency_sandbox_probe.run_probe(...)`. Запуск сетевого наблюдения и его
расписание принадлежат отдельному сервису. Передавать токены или полные ответы
брокера в файл отчёта не требуется.

Код завершения `0` означает успешный выбранный набор проверок программы, `1` —
неподтверждённый или неуспешный набор, `2` — отчёт не удалось записать. Код `0`
не означает, что внешний сервис или реальная торговля готовы.

## API наблюдений

```python
build_report(
    offline_evidence=None,
    sandbox_report=None,
    config_observation=None,
    telegram_observation=None,
    now=None,
    expected_source_fingerprint=None,
)
render_html(report)
source_fingerprint(root=None)
```

`now` — время с часовым поясом; в результате все отметки нормализуются в UTC.
По умолчанию отпечаток рассчитывается по текущим Python-файлам в корне проекта и
в `tools`. Изменение исходного кода снимает подтверждение старой проверки.
Конфигурация и секреты в отпечаток не включаются.

Результат локальных тестов имеет следующий формат:

```json
{
  "status": "VERIFIED",
  "checked_at": "2026-10-07T20:00:00Z",
  "source": "local_unittest",
  "source_fingerprint": "64 lowercase hexadecimal characters",
  "modules": ["all modules in REQUIRED_TEST_MODULES"],
  "counts": {
    "run": 20, "passed": 20, "failures": 0, "errors": 0,
    "skipped": 0, "expected_failures": 0, "unexpected_successes": 0
  }
}
```

Это пример схемы, а не свидетельство пройденной проверки. Для подтверждения
нужен реальный отпечаток, полный выбранный список модулей и непротиворечивые
счётчики. Пропуски и ожидаемые ошибки не считаются успешными тестами. Источник
может быть `local_unittest` или `github_actions`; адаптер CI обязан сохранить
тот же договорённый формат и действительный отпечаток проверяемой версии.

Наблюдение Telegram содержит только результаты проверок именно
`@AxednewsI_bot` и `@axednewz`:

```json
{
  "checked_at": "2026-10-07T20:00:00Z",
  "status": "VERIFIED",
  "bot_identity_verified": true,
  "channel_identity_verified": true,
  "can_post_messages": true
}
```

Отдельное поле `owner_binding_verified` добавляется только после наблюдения
личной привязки. Его отсутствие означает «не проверено» и не снимает уже
проверенные идентичность бота и право публикации. `false` означает наблюдаемое
отсутствие привязки. Отчёт не отправляет проверочное сообщение и не утверждает,
что доставка состоялась.

Необязательное `config_observation` принимает `checked_at` и только настоящие
булевы значения `sandbox_token_present`, `explicit_sandbox_account_present`,
`environment_is_sandbox`. Значения токенов, ID счетов, остатки и условия заявок
отбрасываются. При отсутствии этого аргумента используются булевы наблюдения
из результата проверки песочницы. Ненаблюдённый доступ никогда не объявляется
отсутствующим. Неизвестное значение не заменяется на `false`.

## Что означает состояние

| Состояние | Значение |
|---|---|
| `VERIFIED` | Есть свежее, полное и непротиворечивое подтверждение конкретной проверки. |
| `FAILED` | Проверка зафиксировала ошибку или противоречие. |
| `ACTION_REQUIRED` | Наблюдалось конкретное недостающее условие либо неполное покрытие тестами. |
| `NOT_CHECKED` | Результата нет, он устарел, относится к другой версии или не позволяет сделать вывод. |

Локальное свидетельство действует 24 часа при неизменном исходном коде.
Сетевые наблюдения и наличие конфигурации — 15 минут. Будущее время более чем на
30 секунд не принимается. Работающий сервис пересчитывает свежесть при каждом
запросе; открытая страница перезагружается раз в минуту. Сохранённый статический
HTML остаётся снимком с явно указанными временем проверки и сроком действия.
Повторное построение JSON повторяет проверки свежести.

Успех чтения песочницы подтверждает только чтение данных указанного тестового
счёта. Поля `real_execution_readiness="NOT_CHECKED"` и
`execution_permission_granted=false` остаются неизменными. Состояние реальных
переключателей исполнения из этого отчёта не выводится.

Страница показывает только фиксированные общедоступные названия, состояния,
время, числа тестов и правило CNYRUBf из канонического кода. Она не копирует
полученные описания, тексты ошибок, токены, идентификаторы владельца и счёта,
остатки или детали заявок. Рекомендация владельцу появляется только при
свежем наблюдении конкретного недостающего условия.

## Отдельный сервис диагностики

Точка входа:

```sh
python veritas_currency_automation_server.py
```

Сервис предназначен для отдельного тестового развёртывания из ветки
`feature/currency-sandbox-readiness-20261007`. Он не заменяет работающий основной
сервис. Команды сборки:

```sh
pip install -r requirements-intelligence.txt
python tools/run_currency_automation_report.py --output-dir currency_automation_output --run-offline
```

Для старта необходимы `VERITAS_CURRENCY_AUTOMATION_STAGE=sandbox_readiness` и
`VERITAS_CURRENCY_TRADE_ENVIRONMENT=sandbox`. Все переключатели исполнения,
предложений, торговой консоли и уведомлений должны быть выключены. Сервис
отказывается стартовать при наличии `TBANK_API_TOKEN`, `TELEGRAM_BOT_TOKEN` или
`DATABASE_URL`: ему не нужны доступ к реальному счёту, возможность отправки
сообщений и рабочая база.

Необязательные секретные настройки только две: `TBANK_SANDBOX_TOKEN` и отдельно
указанный `TBANK_SANDBOX_ACCOUNT_ID`. Без них страница доступна и честно показывает
результат наблюдения конфигурации; успешное внешнее подключение не имитируется.
Значения нельзя помещать в адрес страницы или публичные файлы.

Сервис обслуживает только чтение `GET` и `HEAD` для `/`, `/report.json` и `/healthz`.
Действий через HTTP и просмотра файлов каталога нет. Проверка чтения песочницы
обновляется каждые 300 секунд, пока сервис запущен. Локальные свидетельства
обновляются через 12 часов либо после изменения исходного кода; каждое обновление
выполняет выбранные тесты в отдельном процессе без сети с пределом 60 секунд.
Пересчёт свежести на HTTP-запросе не выполняет сетевой запрос к брокеру.

Расписание работает, пока запущен процесс. Страница отражает срок наблюдений и
не обещает непрерывное наблюдение во время его остановки. Сведения о работающем канале и личной привязке должны приходить
из отдельного проверенного наблюдения; диагностический сервис их сам не запрашивает.

## Уведомления о фактических исполнениях

В этой версии восстановлена отдельная очередь `veritas_currency_broker_notifications.py`
и доставка `veritas_currency_broker_delivery.py`. Они предназначены для фактов
брокерского исполнения в @axednewz и не запускаются диагностическим сервером.
Запись события происходит в одной транзакции с новым исполнением: подтверждение
приёма заявки не считается сделкой, повторная сверка не создаёт дубликат,
позднее исполнение учитывается в хронологическом порядке. Неопределённый результат
отправки не вызывает слепой повтор сообщения.

Функция выключена по умолчанию. Требуются отдельное включение
`VERITAS_CURRENCY_BROKER_NOTIFICATIONS_ENABLED`, точные числовые идентификаторы
бота и канала, проверка права публикации и действующая область счёта/владельца.
Пропущенные при выключенной функции события не рассылаются задним числом.
Подтверждения владельца остаются в личном чате, а события модельного портфеля
и фактические брокерские исполнения сохраняют разные очереди.

Внутренний маршрут `/internal/currency-trading/settlement-status` снова показывает
состояние сверки без изменения учёта. `settlement-attest` принимает до 64 KiB в
обоих HTTP-диспетчерах. Проверенный документ и завершённая сверка денежных
операций остаются разными состояниями.
