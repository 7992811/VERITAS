# VERITAS v85 — интеграционный кандидат RC2

**Статус: локальная интеграция выполнена; полная приёмка CI и производственный переход не выполнены. Не загружать в main и не разворачивать на действующем Render.**

Этот пакет объединяет новое ядро управления синтетическими бумажными позициями с полным базовым исходником из пользовательского `VERITAS-main.zip`. Это не очередной `sitecustomize.py`. Реальный сервер, HTTP, 35 аналитических ячеек, учёт, миграция, перезапуски и проверки отказов связаны в одном приложении. Старый модуль `sitecustomize.py` заменён инертным файлом без исполнения; старые автоматические торговые писатели отключены.

## Чего этот пакет пока НЕ доказывает

Локально отсутствует полная историческая зависимость, которую старый загрузчик скачивал из GitHub при каждом развёртывании. Локальная сборка использует полный предоставленный базовый исходник с явно указанным `OFFLINE_BASE_TEST_ONLY`. Она блокируется при обычном производственном запуске. CI отдельно получает точный исторический v80-blob, проверяет Git-хеш, применяет только буквальные таблицы преобразований во время сборки и создаёт статические файлы. Скачанный код не запускается через `exec`.

Локальные финансовые тесты выполнены на SQLite. Написанная PostgreSQL-реализация и её отдельный набор тестов **ещё не выполнены на настоящем PostgreSQL** в этой среде. Для этого есть изолированный PostgreSQL 18 в GitHub Actions. Отчёт PostgreSQL не подменён вымышленным результатом.

Не измерены производственная скорость Render и доходность на новых рыночных сделках. Локальные миллисекунды ответа готового снимка — не измерение живого сервиса. Нет подтверждения роста win rate. Не выполнена репетиция перехода с реальной копией всех текущих позиций.

## Что реализовано

- Один транзакционный владелец исполнения; журнал квитанций, эпизодов, ордеров и уроков. Повторный запрос не списывает повторно комиссию.
- Отсутствие кандидата не закрывает сохранную позицию. Стоп, подтверждённый слом именно её идеи и жёсткий риск закрывают любой положительный остаток.
- Подтверждения разворота сохраняются между циклами и привязаны к времени новой завершённой свечи. Повторный опрос тех же данных не добавляет голос.
- Разворот: закрытие старого эпизода, пересчёт капитала и отдельная проверка противоположного допуска. Стоп не даёт автоматического разрешения открыть обратную позицию.
- Миграция сохраняет остатки, исходные горизонты, учётный капитал, старые комиссии/фондирование. Не создаёт ордеров или новой комиссии, не обнуляет старые таблицы. Несогласованность блокирует перенос.
- Наблюдаемый путь: MFE/MAE, срок удержания, причина выхода, отданная прибыль. Причина ошибки модели не выводится из одного знака P&L.
- Ревизии уроков, время доступности результата, уникальные эпизоды и независимые группы, исключение двойного счёта. Инкрементальный курсор — последовательность записи в БД, не ненадёжное время события.
- Champion — фиксированная контрольная политика; Challenger — ограниченное влияние памяти на размер. Положительный опыт не повышает риск без отдельно подтверждённого допуска по новым данным. Автоматического повышения модели нет.
- Отдельные расписания расчёта, защиты позиций, обновления памяти и проверки аварийного запрета. Готовые HTTP-снимки не запрашивают полную историю и не считают модель.
- Ограниченный пул PostgreSQL, пакетная запись исследовательских решений, таймауты запросов. Межпроцессная аренда права записи v85 с проверкой внутри финансовой транзакции.
- Проверка фактически импортированной версии, а не только текста в файле. Удалён скрытый импортный код V70, заменявший версию хозяина на v72.
- Новостной бот, его подсказки, зависимости и исходный `render.yaml` сохранены. Старые документы/исходники перенесены в архив внутри пакета; удалений в удалённом GitHub не производилось.

## Ограничения предметной модели

Это только исследовательский синтетический портфель. Сохранена старая условность учёта: номинал в рублях делится на уровень котировки. Полученная величина **не является реальным количеством акций или фьючерсных контрактов**. Не реализованы биржевые спецификации лотов/мультипликаторов, брокерские заявки, реальный валютный денежный учёт, гарантийное обеспечение и точные комиссии брокера.

Комиссия задана модельно — 0,05% на сторону. Фондирование новых эпизодов фиксируется по сохранённой при переходе ставке, для коротких позиций добавляется модельный спред 2 процентных пункта. Это не текущий поток RUONIA и не фактический тариф брокера. Старые накопленные издержки переносятся без повторного списания.

Все 7 инструментов и 5 горизонтов остаются в аналитическом экране. Независимый защитный поток котировок сейчас реализован для BTC, ETH и NDX. Для BRENT, GOLD, MOEX, CNYRUBF требуется дополнительная проверка/реализация источников перед передачей ему текущих позиций. Перенос таких открытых остатков блокируется до появления поддержанного защитного адаптера. Нет права заменять отсутствующую вторую прямую котировку прокси или выдуманным временем.

Автоматическое наращивание, обучаемое перемещение стопа, частичная фиксация, полный альтернативный replay пути и обучение направлению **не активированы**. Реализованы исходный допуск, удержание, обязательный выход, подтверждённый разворот и ограниченная настройка первоначального размера. Старые аналитические функции сохранены, но их некалиброванные результаты не получают новую неограниченную власть над исполнением.

Новый быстрый экран не копирует каждую старую панель интерфейса. Полные текущие аналитические строки доступны через `/api/v85/analysis?asset=BTC`; старые тяжёлые панели и административные POST не перенесены автоматически.

Исторические закрытые legacy-сделки остаются в старой базе и доступны для аудита, но автоматически не засчитываются как новые корректно размеченные уроки v85. Для переноса этого опыта нужна отдельная проверка эпизодов, затрат и времени доступности результатов. Новое обучение начинает использовать проверенные новые завершения; прежние некорректные ярлыки не переносятся вслепую.

## Следующий безопасный шаг

Разместить **содержимое** этого пакета в отдельной ветке `v85-acceptance` репозитория, сохраняя пути, особенно `.github/workflows/v85_acceptance.yml`. Не заменять main. Действующий Render, отслеживающий main, на этом шаге не меняется.

Workflow `VERITAS v85 acceptance`:
1. Собирает точную историческую основу с проверкой её хеша.
2. Проверяет статическую версию и манифест исполняемых файлов.
3. Запускает тесты ядра и полного аналитического исходника на фикстурах.
4. Проверяет реальные транзакции на временном локальном PostgreSQL 18 без доступа к производственной базе.
5. Запускает отдельный HTTP-процесс, проверяет версию, 35 ячеек и завершение.
6. Только если все этапы успешны, создаёт артефакт `VERITAS-v85-STAGING-CANDIDATE`.

Зелёный CI означает готовность к изолированному стенду, а **не** разрешение сразу заменить работающий сервис. Реальная копия учёта, живые источники и скорость проходят отдельную репетицию — см. `docs/CUTOVER_RU.md`.

## Локальное воспроизведение

Python 3.11+; полный CI использует Python 3.12. Из корня пакета:

```sh
python tools/build_release.py --offline-base
python tools/run_checks.py
python tools/run_http_smoke.py
```

Первый флаг допустим только для локальной проверки без исторической зависимости. Для строгой сборки убрать `--offline-base`.

PostgreSQL-тесты отказываются работать, если адрес не localhost/127.0.0.1, имя БД не `veritas_v85_ci` или отсутствует явный тестовый флаг. **Они удаляют тестовую схему только в этой изолированной БД. Не переносить их на производственную БД и не обходить ограничения.**

```sh
pip install -r requirements-test.txt
python tools/build_release.py
python tools/validate_core_manifest.py
python tools/run_checks.py
# Сначала поднять временный PostgreSQL по конфигурации workflow.
python ci_tests/test_postgres.py
python tools/run_http_smoke.py
python tools/package_release.py --acceptance
```

`reports/ACCEPTANCE_STATUS.json` перечисляет выполненные и невыполненные проверки. `reports/test_results.json` и `reports/http_smoke.json` созданы действительными запусками, содержат хеш проверенного манифеста.
